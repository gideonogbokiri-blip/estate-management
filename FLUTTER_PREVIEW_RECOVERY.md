### Estate expense workflow (16 November 2026)

### Estate budgets and budget-linked requests (16 November 2026)

- Added versioned, estate-scoped budgets with inclusive date periods, currency and category allocations. Draft creation, submit, maker/checker approval or reasoned rejection are audited. Approved budgets cannot overlap; an exact-period revision supersedes the prior version only if the old version has no approved expense commitments. Period and allocation positivity are checked in PostgreSQL as well as the API.
- Expense requests can reference a same-estate approved budget line for their category, currency and applicable date. The API rechecks the line at submission and final approval, locks it while checking remaining allocation, and blocks concurrent approvals from committing more than the category allocation. Budget summaries derive committed amounts from approved expense records; they do not claim payments or paid actuals.
- The manager page now shows budget versions, line allocations, committed and available amounts, and approval actions. Policy setup lets the estate explicitly require a budget line or permit unbudgeted requests. The additive migration `20261121150000_estate_budgets` is deployed; Nest build and schema validation succeeded, Flutter admin release bundle rebuilt, readiness returned HTTP 200, and the unauthenticated budgets endpoint returned HTTP 401 as expected.

### Manual expense payment reconciliation (16 November 2026)

- Finance managers and estate administrators can reconcile a partial or full expense payment after checking the bank record. The API locks the expense, validates the outstanding balance and currency, rejects duplicate estate bank references and overpayment, supports idempotent retries, and atomically stores the settlement, updates the derived expense state and appends an audit event. Stable receipt references and received amounts appear in the manager UI and expense budget summaries.
- The additive migration `20261121160000_estate_expense_settlements` is deployed. Backend build and Prisma schema validation succeeded; the expense page analyzes cleanly and its Flutter release bundle rebuilt. This is staff-entered reconciliation only: there is no bank feed, payment initiation, refund/reversal workflow or downloadable receipt document.

### In-app estate notifications (16 November 2026)

- Added a private, persisted notification inbox at `GET /api/v1/notifications/mine` and an idempotent recipient-scoped read action. Resident and manager app bars link to the inbox; notices show the estate, safe event summary and read state. Active membership is checked on every inbox read.

New incident reports notify active estate reviewers and status transitions notify the reporter. Notice writes share the source-event transaction and are de-duplicated per estate, recipient and event key. This release remains in-app only; no push, email or SMS is sent.
